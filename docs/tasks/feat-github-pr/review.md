# GitHub PR 发布流程审查

## ✅ 优点

发布前界面展示仓库、源分支、短 SHA 和目标分支。后端根据 Workspace 与仓库 ID 打开实际仓库，重新核对本地 HEAD，并读取 GitHub 的源分支 SHA；只有两端一致才会提交用户编辑过的标题和正文。返回链接由已验证的仓库名和 GitHub 响应中的 PR 编号组成。

## 🔴 严重问题（必须修复）

已修复 GitHub CLI 超时无法覆盖写入标准输入的问题。写入大段正文时，若 CLI 正在等待且未读取输入，原实现会在启动超时计时前卡住。正文改为并行写入，并新增不读取输入的子进程回归测试。

## 🟡 一般问题（建议修复）

创建失败原先共用未翻译的错误码。现已为无效目标、分支变化、未推送提交、CLI 未安装、超时等情况补齐稳定错误码和中英文文本。系统浏览器打开失败时，窗口会显示错误并保留已创建的 PR 链接，用户可以再次打开。origin 校验也已覆盖 GitHub 的特殊仓库名 `.github`，同时拒绝路径中的 `.` 与 `..`。

## 🟢 优化建议（可选）

本轮无额外建议。

## 📝 总体评价

核对、确认创建、失败后继续编辑与查看成功结果均有自动化覆盖。远端 SHA 检查与 GitHub 创建请求是两个 API 调用，期间远端分支仍可被其他用户更新。验证使用临时仓库、模拟 API 和本地子进程，未向 GitHub 发布真实 PR。

5 项 Rust 测试及 7 项前端交互和翻译一致性测试通过，TypeScript 与修改文件的 ESLint 检查通过。
