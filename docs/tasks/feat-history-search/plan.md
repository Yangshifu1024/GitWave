# History 提交搜索与定位

[路线图第 3 项](../../pm/core/03-roadmap.md#25-后续功能优先级) · [工作台设计](../../design/09-workbench-redesign.md#52-history)

## 用户故事

我在 History 审阅当前仓库时，想用一段提交说明、作者信息或短 SHA 找到某次提交，并在完整提交图中查看它与前后提交的关系。

## 实现范围

- History 的搜索入口直接打开当前仓库的本地提交搜索。支持按 SHA、提交标题或正文、作者姓名或邮箱进行大小写不敏感的子串匹配。全局命令面板仍有自己的快捷键和流程。
- 复用 `useCommitPages` 和 `cmd_get_commit_page`，按查询防抖请求。使用已有游标继续扫描，显示已扫描条数、快照范围和截断提示。一页没有命中但还有游标时，继续扫描仍可用。
- 按选中结果的完整 SHA 定位原提交图，并在详情区展示该提交。搜索不执行 checkout。键盘和鼠标均可选择结果。
- 查询、仓库或 Workspace 改变后，旧查询响应不能覆盖新结果。空查询、扫描中、无匹配、错误及重试均有可识别的状态。
- 本轮只搜索提交元数据。路径历史和分支高级筛选单独排期。

## 验收

| 场景 | 预期行为 |
|---|---|
| 本地仓库包含消息正文、作者邮箱或短 SHA 命中 | 在 History 中输入关键词会返回对应提交，无需发起 AI 请求 |
| 第一页没有命中，后续页包含目标 | 显示进度，继续扫描后可定位该提交 |
| 选择提交图当前未加载的结果 | 按已有定位流程加载所需页并选中正确的 SHA |
| 达到快照上限或请求失败 | 能区分已扫描范围和全部历史，失败时提供重试 |
| 快速切换仓库或修改查询 | 活动结果和后续翻页仅属于当前查询与仓库 |
