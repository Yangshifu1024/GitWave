# Changes 提交流程审查

审查基线为 `origin/main`（`9c39bff`）。检查范围包括普通 commit 与 amend 的返回值、跨仓库的异步回调、文件选择回退和编辑器实际尺寸。

## ✅ 优点

- 查看入口使用 Git 刚返回的完整 SHA。只有用户点击才切换到 History，未暂存的改动可以留在 Changes 中继续处理。
- 列表更新后，仍存在的原侧路径继续选中。原侧路径消失时，先向后、再向前寻找原侧邻项，随后才回退到另一侧的同一路径。缺少候选时清空选择。

## 🔴 严重问题（必须修复）

**提交期间换仓库会丢失查看入口，已修复。** 原先 SHA 保存在面板局部状态中，面板卸载后即使 Git 成功也找不到结果。现按发起请求时的 Workspace 和仓库保存 SHA。回归测试在仓库 A 提交、切到 B，再让请求完成，验证 B 不出现 A 的查看入口，回到 A 后能显式定位完整 SHA。

## 🟡 一般问题（建议修复）

**调大编辑区只增加空白，已修复。** 原先分隔线改变容器高度，但多行输入框始终只有四行。现让输入框使用可调区域的剩余空间。使用 Chromium 渲染实际组件和项目样式，编辑容器从 310 px 增到 460 px 时，输入框从 202 px 增到 352 px。分隔线键盘调整另有组件测试。

## 🟢 优化建议（可选）

选择仍有效时已直接返回，避免在同一文件保持选中的常规刷新中为每条变更重建邻项索引。

## 📝 总体评价

提交成功只更新发起仓库的会话，失败不产生新的查看入口。三组定向测试共 14 项通过，覆盖跨仓库提交结果、amend 的替换 SHA、剩余未暂存文件、选择回退以及分隔线键盘操作。TypeScript 全项目检查和变更文件 ESLint 检查均通过。
