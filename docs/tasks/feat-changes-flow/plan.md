# Changes 提交流程

[产品路线图第 4 项](../../pm/core/03-roadmap.md#25-后续功能优先级)

## 提交后查看

commit 或 amend 成功后，在发起操作的仓库提供查看结果的入口。用户选择该入口再切换到 History，按这次操作返回的 SHA 定位。存在剩余变更时仍可留在 Changes 继续工作。

## 选择与布局

Stage 或 unstage 后，先保留原侧的同一路径。如果该项消失，从原侧列表向后寻找仍存在的邻项，再向前寻找。只有原侧邻项都已消失时，才跟随原路径到另一侧。三者均无匹配时清空选择。允许调整文件列表与提交编辑区之间的高度，给长提交说明留出空间。

## 验证

覆盖普通 commit、amend、提交失败、操作期间切换仓库及保留的未暂存改动。例如未暂存列表依次有 A、B、C：暂存 B 后选中 C；若 C 也已移除则选 A。若原侧只剩 B 且 B 被移到已暂存侧，则跟随 B。部分暂存后 B 仍在原侧时，继续查看原侧的 B。
