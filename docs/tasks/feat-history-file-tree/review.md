# History 提交详情变更文件树审查

审查基线为 `origin/main`（`0f4d9f9`）。范围包括工作区相对基线的修改，以及新增的文件树组件、路径处理函数、回归测试和任务文档。

## ✅ 优点

- 初始选择优先恢复当前仓库会话中与提交匹配的有效路径，否则沿已排序的目录树选择第一个文件。文件树在摘要到达后挂载，初始只展开选中路径的祖先。
- 选择文件时沿用原始完整路径查询 diff。折叠和展开目录只更新文件树的本地状态，同一提交刷新可保留折叠状态。Workspace、仓库或提交变化时会重新初始化文件树。
- 文件和目录分开建模，同一提交将文件替换成同名目录时，原文件和目录中的新文件都可选中。

## 🟡 一般问题（建议修复）

**计数回归已修复。** 后端会把 Git 路径转换为可显示的 Unicode 文本，Unix 上两个含有不同非法 UTF-8 字节的文件名可能产生相同的显示路径。初版用唯一路径数作为标题计数，会少算文件。已复核标题改用摘要条目数，叶节点的 React 键也能区分同名行。按显示路径读取 diff 的既有接口仍无法区分这类碰撞。
