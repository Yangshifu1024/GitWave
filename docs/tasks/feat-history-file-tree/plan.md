# History 提交详情的变更文件树

[F018 工作台设计](../../pm/features/F018-workbench-redesign.md) · [路线图第 3 项](../../pm/core/03-roadmap.md#25-后续功能优先级)

## 目标与范围

审阅跨目录的 commit 时，开发者可以折叠已经看过的目录，定位同名文件并继续阅读当前 diff。本次交付 History 提交详情中的变更文件树。History 独立搜索另行排期。

## 实现逻辑

1. 复用 History 已取得的 commit diff 摘要。用 Git 返回的完整路径按 `/` 构造目录层级，每层先列目录再列文件，同类按名称排序。保留原始路径作为文件身份和 diff 查询参数，无需遍历工作目录或推断重命名。
2. 优先选中当前仓库会话记住的文件，条件是 commit 匹配且该路径仍在摘要内。否则选树序中的第一个文件。初始只展开选中文件的祖先目录；根目录下的文件直接可见。
3. 点击文件更新选择并复用现有按文件加载的 diff。点击目录、全部展开或全部收起仅改变树的显示，包括收起当前文件所在目录。标题中的数量按变更文件计数。
4. 同一提交刷新时保留展开状态。切换仓库或 commit 时按新目标重新确定选中项并初始化展开状态。加载、重试和空提交沿用现有详情区。

## 验收

| 操作或数据 | 可观察结果 |
|---|---|
| 打开含根文件、嵌套目录和同名文件的提交 | 同级目录在前，两个同名文件可分别选中，diff 对应各自的完整路径 |
| 打开有记忆路径的提交，或打开没有记忆路径的提交 | 分别选中记忆文件、树序首个文件，且选中行可见 |
| 展开目录、收起当前文件的祖先、全部展开或收起 | 当前 diff 持续显示；操作目录不会加载其他文件内容 |
| 刷新当前摘要，再切至其他 commit 或仓库 | 刷新保留折叠选择，新目标重新初始化 |
| 打开无变更文件的提交，或重试加载失败的提交 | 详情区正确显示空状态或提供重试入口 |
