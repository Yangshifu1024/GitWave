# 两提交比较与路径历史审查

## ✅ 优点

路径扫描从固定提交出发，比较当前树和第一父树中的对象及模式。每页扫描至多 128 项，下页从首个未访问的父提交开始。实仓用例涵盖空页继续、根提交、重命名、删除以及 merge 的第一父差异。

## 🔴 严重问题（必须修复）

- 路径历史结果原先只更新详情 SHA，提交图无法找到尚未加载的项。已接通工作台的完整 SHA 定位逻辑，恢复图可见并按需翻页、居中。
- 原比较接口在选择文件前就生成两个提交之间所有文件的完整补丁。已接入受限的预览接口，先取文件摘要，再按完整路径取一份补丁；超过常规预览上限时可提高一次上限。实仓测试使用两个不同分支的提交，并验证交换基点、目标后新增行变成删除行。

## 🟡 一般问题（建议修复）

路径历史后续页失败时，重试曾重读已成功的页面。现从失败的游标重试，保留之前的结果。二进制或仅元数据变动也有明确的无文本提示。

## 🟢 优化建议（可选）

本轮无额外建议。

## 📝 总体评价

三组前端定向测试共 16 项通过，Rust 路径历史与 diff 预览共 8 项通过；TypeScript 与变更文件 ESLint 通过。比较和路径回溯均为只读操作。
