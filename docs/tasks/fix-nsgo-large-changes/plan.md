# NSGo Changes 大列表卡顿与布局修复

## 复现

用户在 macOS 用 Go 版打开当前 GitWave 仓库时遇到界面变形、掉帧和卡顿。把当前工作树的 495 条变更复制到隔离仓库。1200×800 的 AppKit 窗口中，Changes 分栏约 656 点高，未暂存列表视口却达到约 6,946 点，导致虚拟列表提前挂载大量行，并将暂存列表及提交编辑器挤出窗口。模型在 1024×768 同样复现。

## 修复和验收

- 让 Changes 文件栏内的两个纵向容器按当前分栏高度收缩。各文件区的横向滚动标题保留固定高度。
- 用真实临时仓库生成 495 个未暂存文件，在两种窗口尺寸检查视口和挂载行数。滚动到末尾，选择文件查看 diff，并在提交编辑器输入。
- 在同一份 495 条变更的复制仓库中重新运行 AppKit 采样。比较打开 Changes 时的布局、挂载规模及开销，再跑既有的提交、暂存、冲突和刷新回归。
