# NSGo Changes 大列表验收

## 原因与修复

Changes 文件栏的两层纵向容器原先按长列表的内容高度参与布局，无法收缩到分栏的实际高度。虚拟列表把异常尺寸当成可见范围，同时挂载大量行。两层容器加入纵向收缩，区块标题用 NSGo `NoShrink` 保持 32 点高，横向溢出仍可滚动。

## macOS 原生复测

| 同一份 495 条变更、1200×800 窗口 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 未暂存列表视口 | 约 6,946 点 | 192.5 点 |
| 切到 Changes 时最大单批 NSGo 挂载指令数 | 12,440 | 668 |
| 暂存区与提交编辑器 | 超出可见区域 | 留在窗口内 |

修复后 AppKit 初始挂载 14 个文件行，列表内容仍有 13,860 点。缩到 1024×768 后，视口为 176.5 点，两个标题、暂存区和提交编辑器仍可见。实际流程跑过滚动、窗口缩放和切换 diff。NSGo 指令数取自相同测试动作的 trace，用于描述挂载工作量。

`make check`、定向竞态测试和 5 项 AppKit 交互回归通过，覆盖 495 文件的末尾定位、diff、提交编辑器输入，以及暂存、取消暂存、commit/amend、冲突完成和变化刷新。独立模型复审在 229 点宽的文件栏检查了 495 条全暂存和全冲突数据，两种情况均保留可见标题，末尾文件可达。大列表回归已加入 macOS 原生 CI。

修复版 Apple Silicon 预览 DMG 已核对 SHA-256，挂载内应用通过严格代码签名验证。预览使用 ad hoc 签名。复现和测试使用隔离仓库，未在用户工作树上运行暂存、提交或清理。

## 未跟踪文件的文本预览

未跟踪文本直接统计文件的总新增行数，只生成预览范围内的行。普通和展开预览沿用原有字节、行数和单行字符上限，也保留 CRLF、末尾无换行和非法 UTF-8 的原有显示。

Apple M4 上以同一份 1,045,000 字节、19,000 行的文本测试，前后各运行三组 80 次。预览中位耗时从 1.47 毫秒降至 0.78 毫秒，每次分配从 9.03 MiB 降至 3.36 MiB。已有的 495 文件原生用例在列表末尾增加长文本，验证预览截断时文件区和提交编辑器仍可操作。

普通和展开预览共 218 项对照样本的行号、总数、文本和截断结果与旧路径一致。macOS 的大列表、暂存两侧切换、重命名刷新后三项 AppKit 回归，以及 Git diff 定向竞态测试和 `make check` 通过。

在另一份 495 条混合改动的副本中，重命名扫描耗时约 195–215 毫秒。其中复制 436 个候选文件约 66 毫秒，更新临时索引、Git 相似度比较和内容哈希约 90 毫秒。本轮数据指向后续刷新性能仍需处理的具体路径。

使用同一混合改动副本在 AppKit 中滚动、缩到 1024×768，再反复切换两个 diff。列表仍限定在分栏内，提交区保持可见。NSGo 在测试动作中的持续滚动样本为 59–60 FPS，初次启动的采样窗口仍记录到掉帧。

## 混合重命名的重复扫描

刷新先验证候选文件内容、模式、源对象、仓库内的属性快照和 Git 配置。输入一致时复用上一次同一仓库的 Git 配对结果，省去重建临时索引和再次执行相似度比较及内容哈希。存在系统或全局属性文件时执行完整比较。候选文件读取按已打开文件的大小分配缓冲区，并继续限制文件增长时可读取的字节数。

Apple M4 上用同一份 495 条混合改动和 11 对移动做前后比较，每个版本各运行三组 15 次。重复扫描的中位耗时从约 189 毫秒降到约 112 毫秒，单次内存分配从 8.82 MiB 降到 5.45 MiB。完整比较和复用结果的配对路径、内容签名及对象 ID 一致。暂存前会再次核对工作树内容和转换后的对象 ID。

全局属性路径复核发现 Git 的显示路径可能化简 `..`。缓存和暂存读取私有 Git 的实际全局属性配置，保留符号链接之后的父目录组件。对绝对、相对和 XDG 默认配置分别验证，暂存后的对象都保留预期的 LF 转换。新增回归也覆盖了大小与修改时间相同的内容改写、目录属性和 info 属性变化，以及调用方修改返回值。 [Git 的变量输出实现](https://github.com/git/git/blob/v2.54.0/builtin/var.c#L59-L76) [Git 的属性读取实现](https://github.com/git/git/blob/v2.54.0/attr.c#L822-L878)

三项 AppKit 回归通过，覆盖 495 文件、移动文件暂存与取消暂存，以及外部改动后的选中项恢复。SHA-1、SHA-256 定向竞态测试和并发缓存复测通过，取消扫描没有替换已有结果。Linux 与 Windows x64 测试二进制交叉编译和 `make check` 通过。

## 重命名扫描的临时副本

已有配对时先在内存中保留最多 4 MiB 的候选文件缓冲。预算内命中直接复用 Git 配对，候选文件无需写入临时工作树。输入变化或超过预算时继续使用私有工作树完成完整扫描。同一目录内的副本共享已验证的目录句柄。候选普通文件采用打开句柄后的模式和时间戳，覆盖同 inode 的可执行位变化并拒绝不同 inode 的路径替换。

Apple M4 上同一份 495 条混合改动和 11 对移动的配对结果、内容签名及对象 ID 一致。下表为三组重复试验的中位数，首次扫描和连续刷新每组运行 12 次，改写一个不属于配对的候选后重扫每组运行 10 次。

| 场景 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 首次完整扫描 | 199 毫秒 | 186 毫秒 |
| 输入稳定的连续刷新 | 113 毫秒 | 51 毫秒 |
| 改写一个候选后重扫 | 200 毫秒 | 186 毫秒 |

超过 4 MiB 的端到端夹具验证了落盘后的配对与缓存一致，完整扫描保留原索引，之后仍可正确暂存移动。三项 AppKit 回归、定向竞态测试、Linux/Windows x64 交叉编译和 `make check` 均通过。

## 首次打开混合变更

Changes 等完整配对结果后一次更新列表，延续旧版行为。macOS 和 Linux 在读取候选文件时解析外部 Git 属性路径，并在比较前检查这些文件是否存在。属性快照完整时，Git 相似度比较与候选内容哈希并行读取同一份私有索引和工作树。没有配对时取消哈希，所有这一轮启动的 Git 命令都在清理临时工作树前结束。存在外部属性时按顺序比较和哈希。Windows 保留顺序读取，避免取消 Git 启动器后受其子进程继承的输出管道阻塞。

Apple M4 上同一份 495 条混合变更在两版中均识别出 11 对移动，配对路径、内容签名和转换后的对象 ID 一致。另测 456 条变更的无配对仓库。下表为每组 12 次、共三组的扫描耗时中位数。

| 重命名扫描 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 495 条变更，首次完整扫描 | 195 毫秒 | 165 毫秒 |
| 495 条变更，稳定输入下重复扫描 | 53 毫秒 | 43 毫秒 |
| 456 条变更，无配对，首次扫描 | 122 毫秒 | 112 毫秒 |

三项 AppKit 回归验证了 495 条变更的缩放和末尾定位、移动文件刷新后的选中状态，以及一并暂存和取消暂存移动的两端。`make check`、SHA-1 和 SHA-256 定向竞态测试、并发扫描与取消、Linux 和 Windows x64 交叉编译通过。新增进程取消回归会让 Git 启动器的子进程保留输出管道，确认空配对能结束进程组。移除进程组配置后，同一用例会检测到子进程继续运行。

同一份 495 条混合变更的隔离副本通过 AppKit 往返滚动、缩到 1024×768、键盘定位首尾和切换 diff。提交区仍在视口内。连续滚动的四个一秒采样均为 59 FPS，启动后的第一个采样仍记录到掉帧。帧率来自 NSGo 性能监视器。

## Changes 状态的引用查询

Changes 每次读状态时只查询当前分支以及它的上游计数。History 等需要完整分支和标签列表的入口继续枚举引用。Git 查询在计算计数前排除当前分支下的子引用，避免未出生分支因同名前缀的损坏子分支而读状态失败。自定义 fetch 命名空间采用 Git 的计数结果，欠缺上游历史时沿用旧行为，保留上游名称和零计数。 [Git 引用查询](https://github.com/git/git/blob/v2.46.0/Documentation/git-for-each-ref.txt#L28-L50) [Git 跟踪计数](https://github.com/git/git/blob/v2.46.0/Documentation/git-for-each-ref.txt#L144-L164)

Apple M4 上用相同的 495 条变更比较状态读取。普通仓库各运行三组 16 次，附加引用仓库各运行三组 12 次。两版的普通仓库和附加引用仓库均逐字段比对了状态快照，路径、暂存内容和分支字段一致。

| 状态读取 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 495 条变更 | 69 毫秒 | 55 毫秒 |
| 495 条变更加 6,000 个引用 | 261 毫秒 | 84 毫秒 |

6,000 个附加引用由 3,000 个分支和 3,000 个标签组成。该场景单次状态读取的内存分配从约 8.46 MiB 降到 0.78 MiB。AppKit 用同一份夹具打开了 483 行并复测 1024×768 窗口、滚动、最后一行定位和 diff 预览。计时只涵盖状态读取。

清空移动配对缓存后，状态读取和两侧移动识别合计的中位时间从 556 毫秒降到 314 毫秒，每版各运行三组 8 次。两版均识别同一组 12 对移动。计时截止于数据准备就绪。

Git 2.46 和 Apple Git 2.54 的定向竞态验证通过，覆盖分离 HEAD、未出生分支、标准与自定义上游、损坏的子引用、上游删除与历史缺失。独立夹具也验证了 linked worktree、shallow、loose、packed 和 reftable 引用。四项 AppKit 回归、Linux 和 Windows x64 交叉编译及完整 `make check` 通过。
