# 冲突处理与交互式 rebase 审查

## ✅ 优点

操作区域依据 Git 状态区分 merge 与孤立 index 冲突。最后一个文件标记解决后，仍可看到尚待完成的 merge。键盘移动复用已有 todo 顺序和执行校验，重排本身不会执行 rebase。

## 🔴 严重问题（必须修复）

切换到无冲突的仓库会关闭面板并清掉另一仓库的未保存草稿，已修复。缓存按 Workspace、仓库和文件隔离，首次轮询期间保留草稿。取得真实状态后清理已结束冲突，再次打开时核对文件三侧和工作区内容。回归测试覆盖 A 编辑、访问 B、返回 A 恢复、原操作结束及同路径再次冲突。

## 🟡 一般问题（建议修复）

暂停操作的全局控件曾依赖侧栏折叠区域挂载，已将 portal 移到折叠区外。未保存标记改由 React 状态驱动，移除了渲染期间读取 ref 的问题。

## 🟢 优化建议（可选）

本轮无额外建议。

## 📝 总体评价

冲突编辑、仓库状态隔离和交互式 rebase 三组前端测试共 11 项通过。审查覆盖确认放弃草稿、保存失败、陈旧响应、孤立冲突、解决后等待提交，以及键盘上下移和列表边界。
