# 部分暂存与取消暂存审查

## ✅ 优点

后端重新生成 patch、核对预览令牌并验证所选行，再将修改仅应用到 index。临时 Git 仓库用例直接读取 index blob 和工作区正文，涵盖行级替换、相同上下文中的不同 hunk、空文件、取消暂存和外部改动。

## 🔴 严重问题（必须修复）

原令牌只取决于 patch 文本。两个仓库有相同 patch，或两个方向呈现完全相同的改动时，旧令牌也可通过。现将 Git 仓库路径身份、操作方向和含完整 blob ID 的 patch 共同绑定。补充实仓测试，在两个仓库及同仓库两个方向间互换令牌均被拒绝，index 保持原内容。

## 🟡 一般问题（建议修复）

2 MiB 上限原先在序列化完整 patch 后检查，现先读取 libgit2 的 patch 大小。路径参数在进入 libgit2 之前进行检查。中文和英文界面均可识别过期或不支持的预览错误。

## 🟢 优化建议（可选）

本轮无额外建议。

## 📝 总体评价

6 项真实 Git 仓库定向测试全部通过。核对了按 hunk/行的实际 index 变更和拒绝条件，确认整文件操作继续独立可用。
