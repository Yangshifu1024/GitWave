# F015 · ActionBar 编辑器按钮（在编辑器中打开仓库）

## 背景

用户在 GitWave 中浏览仓库时，经常需要直接跳到代码编辑器（Visual Studio Code / Zed / VSCodium）中继续编码。F014 已提供「文件」「终端」外部打开入口，但缺少编辑器入口，用户仍需手动打开编辑器再定位到仓库目录。

## 提议方案

在 ActionBar 左侧「文件」「终端」按钮旁新增「编辑器」按钮：

1. **检测本机安装的编辑器**：按 Visual Studio Code → Zed → VSCodium 顺序探测（Windows 已知安装路径 + PATH、macOS 应用包存在性、Linux PATH），仅列出实际检测到的编辑器。
2. **点击按钮弹出下拉列表**：列表按检测顺序排列，第一个检测到的编辑器排最前（作为默认）；点击任意一项即在**当前活跃仓库**根目录打开该编辑器。
3. 未检测到任何受支持编辑器时按钮禁用，tooltip 提示未检测到。

### 行为细节

- 按钮作用于**当前活跃仓库**，与 F014 的文件/终端按钮一致；无活跃仓库或仓库 missing 时禁用。
- 打开动作由 Rust 侧 spawn 完成（detached），目录同时作为子进程工作目录与启动参数。
- 纯只读操作：不涉及 git 状态修改，不违背「AI 不自动 commit/push/merge」原则。
- 打开失败（编辑器启动失败等）向用户展示错误提示。
- 编辑器检测不做持久化记忆，固定以检测顺序第一个为默认。

## 影响

- 涉及模块：ActionBar（前端）、Tauri command（后端）、i18n（en / zh-CN）
- 影响版本：0.7.x
- 是否破坏向后兼容：纯新增功能，无破坏性变更
