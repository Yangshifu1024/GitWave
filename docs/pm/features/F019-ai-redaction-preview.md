# F019 · AI 发送前脱敏与本地预览

**状态**　已接受，待发布

## 用户故事

我在仓库里处理客户联系方式和访问凭证。使用 AI 解释提交时，我想先看这次会发出哪些文字，再决定是否发送。对我已经熟悉的操作，我希望仍能一键生成。

## 产品范围

适用于 commit message、PR 描述、commit 解释、冲突解释、命令面板 Ask AI、仓库健康解释和 reflog 解释。每个入口都提供直接生成和发送前预览。预览在本机显示完整的系统提示、用户内容，以及邮箱处数、电话处数和凭证行数。关闭预览即放弃本次发送。

系统提示和用户内容均适用同一组规则。先按已有规则遮盖疑似凭证和私钥，再将剩余行中的常见邮箱和可识别的电话号码替换为占位符。脱敏覆盖的具体格式见下表，姓名、地址及其他正文仍可出现在预览中。

| 输入示例 | 预期结果 |
|---|---|
| `TOKEN=DEMO_ONLY` | 整行替换为 `[REDACTED]` |
| `联系 team+docs@example.org` | `联系 [EMAIL]` |
| `英国 +44 1632 960123` | `英国 [PHONE]` |
| `手机 13800138000` 或 `手机 138 0013 8000` | `手机 [PHONE]` |
| `值班 (202) 555-0142` | `值班 [PHONE]` |
| `git@example.org:demo/app.git`、`v1.2.3`、常见提交 SHA 和时间戳 | 保留 Git 上下文 |

## 验收条件

- 打开或关闭预览时，所有 provider 的请求数均为零。
- 从预览确认发送后，主 provider 和故障转移使用的系统提示与用户内容逐字匹配预览，即使在查看期间暂存内容发生变化。
- 切换 Workspace、仓库、任务或目标对象后，旧预览不能用于新目标。预览内容仅保存在本次会话的内存中。
- 直接生成也按同一组规则脱敏。已有离线策略继续约束实际发送。
