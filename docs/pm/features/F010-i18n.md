# F010 · 完整国际化（UI 中英双语 + AI 回复语言）

## 背景

产品原则（`docs/pm/core/01-features.md` §1.10）已承诺「中文 + 英文一等公民；本地化：中文 / English 双语」，v0.1 bootstrap 时被显式推迟（`docs/tasks/feat-bootstrap-tau-app/plan.md`：v0.1 期间先用英文）。当前应用 UI 全量硬编码英文（约 34 个组件 + 菜单常量表 + hooks/stores 状态消息），Rust 后端 228 处 `AppError` 英文消息经 IPC 直接展示，中文用户阅读成本高。同时 AI 交互（commit message / PR 描述 / 冲突解释等）固定英文回复，中日韩用户需以非母语阅读 AI 产出。

## 提议方案

- **UI 语言（应用级，存 localStorage）**：Settings → General 新增「UI language」，中文 / English 二选一，选择后即时生效（无需重启）；默认跟随系统语言。前端引入 react-i18next，全部用户可见文案 key 化（含应用菜单、命令面板、状态 / toast 消息、Rust 错误消息按 code 前端翻译）
- **AI 语言（应用级，存 localStorage）**：Settings → General 新增「AI language」，中文 / 日本語 / 한국어 / English 四选一；每次 AI 调用时语言随 IPC 传入，Rust 在所有散文产出 system prompt 尾部追加回复语言指令；默认 English
- **错误消息 key 化**：Rust `AppError` 附稳定 code + 参数，英文原文作 fallback，前端按 code 翻译
- **对外载体**：README 增中文版（`README.zh-CN.md`，顶部互链）；官网 site 按浏览器语言自动适应（zh 访客自动进入中文页，无手动切换器）

不做：AI prompt 主体翻译、predefined 菜单项翻译（系统自带本地化）、品牌名翻译、官网手动语言切换。

## 影响

- 涉及模块：前端全部组件与 hooks/stores 文案（`src/i18n/` 新增）；Rust：`domain/error.rs` + `domain/error_codes.rs`（新）、`infrastructure/ai/`、`application/use_cases.rs`、`lib.rs` AI 命令签名；`site/`、`README`
- 影响版本：v0.6.0
- 是否破坏向后兼容：否（无设置时默认英文 / 跟随系统，行为与现状一致；错误序列化仅新增可选字段）
